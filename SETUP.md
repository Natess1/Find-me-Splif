## 1. Сцена обучения (TutorialScene)

1. `File → New Scene → Basic (2D)` → сохрани как `Assets/Scenes/Levels/Menu/TutorialScene.unity`
2. Создай пустой объект `Tutorial` → повесь на него скрипт **TutorialPager**
3. Перетащи в сцену префаб перехода: `Assets/Prefabs/Scenes/NewSceneTransition.prefab` — тот же, что в главном меню. Подойдёт и старый `SceneTransition.prefab`: скрипт сам подбирает имена триггеров аниматора (sceneEnd/sceneStart либо Close/Open) и не зависает, даже если в клипе нет анимационного события
4. `File → Build Settings → Add Open Scenes` — добавь TutorialScene в билд (ОБЯЗАТЕЛЬНО)
5. Запусти — всё уже работает:
   - 5 страниц: «!» → Ходьба → Дэш → Атака → Хил
   - «!» вшит в заголовок первой страницы (красный, сразу после текста)
   - стрелки гаснут серым на первой/последней странице
   - «В МЕНЮ» возвращает в главное меню

### 1.1. Фон как в главном меню

1. В инспекторе объекта `Tutorial` найди поле **Background Prefab**
2. Перетащи туда префаб `Assets/Prefabs/Scenes/NightBG` — это 4 слоя с Paralax (те же механики, что в меню)
3. Код сам: поставит камере **CameraParallax** (скорость 0.5, разворот каждые 50 сек — как в MainMenu), свяжет все слои Paralax с камерой (в префабе ссылка на камеру пустая — она хранится только в сцене)

Поля в инспекторе:
- **Background Scale** — если слои выглядят мельче/крупнее, чем в меню, крути этот множитель
- **Menu Camera Speed / Moving Time** — скорость и время проезда камеры
- **Background Darkening** — затемнение фона под текстом (0 — без затемнения)

Другой цвет фона (GlodenSun / SunrizeBG — спрайты в `Assets/Sprites/UI/BG/`): добавь NightBG, затем в Hierarchy у его слоёв MainBG(1–3) и NightBG подмени Sprite у SpriteRenderer на спрайты из другой папки.

### 1.2. Видео-«гифки» в окнах обучения

Страницы (кроме «!») играют зацикленное видео — «гифку». Unity gif не проигрывает, зато отлично играет mp4 (H.264). Видео полностью некликабельно (касания проходят мимо) — листать страницы можно, не задевая ролик.

Как добавить свои ролики (имена файлов фиксированы!):
1. Запиши короткие повторяемые куски 5–15 сек: ходьба, дэш, атака, покупка хила у торговца
2. Обрежь (можно прямо на телефоне) и назови ТОЧНО так: `Walk.mp4`, `Dash.mp4`, `Attack.mp4`, `Heal.mp4`
3. Создай в проекте папку `Assets/Resources/Tutorial/Videos/` и перетащи файлы туда
4. Готово — больше ничего нажимать не нужно: скрипт сам находит клипы по этим именам, крутит по кругу (loop) и вписывает в окно

Нюансы:
- Пока ролика нет — страница показывает только заголовок и текст (спрайт-анимации из стандартных страниц убраны)
- Если видео не играет — сначала проверь, что TutorialPager.cs свежий: открой файл и поищи `OnVideoError` (Ctrl+F). Нет такой строки — распакуй свежий `find-me-splif-changes.zip` в корень проекта с заменой (в старой версии был белый квадрат)
- Свежая версия вместо белого квадрата показывает причину прямо в окне обучения (красная надпись — Console на телефоне не видно) и пишет её в Console. Дальше по надписи:
  - «Видео не найдено: Tutorial/Videos/…» — файл не там или имя не точное. Нужно ровно: `Assets/Resources/Tutorial/Videos/Walk.mp4` (+ Dash, Attack, Heal), расширение .mp4, без двойного «.mp4.mp4»
  - «Видео не воспроизводится: …» — почти всегда кодек: телефоны часто пишут экран в HEVC (H.265), который плеер Unity не декодирует. Фикс: выдели все 4 клипа в Project → в Инспекторе в блоке VideoClip включи **Transcode**, Format = **H.264** → Apply (кадр станет 4:2:0 8-бит — играбельно везде)
  - Если сам Transcode падает с ошибкой (в Windows нет HEVC-кодека) — перекодируй файлы бесплатным HandBrake: Video Codec = H.264 (x264), Framerate = 30, Constant Framerate, затем перетащи в проект заново
- Тестируй видео в Game view редактора или через Build And Run на телефоне. **Unity Remote видео не показывает** — через него «видео не работает» всегда, это не баг
- Окно выше, чем 16:9 — горизонтальный ролик будет с небольшими полосами сверху/снизу. Хочешь вплотную — записывай ближе к 4:3
- Назначить клип вручную тоже можно: Pages → у страницы поле **Video** (приоритет: Video → путь в Resources)

Настройки в инспекторе TutorialPager: цвета окна/текстов, спрайты стрелок, Top Margin (отступ «Обучение» от верха, 30–50).

## 3. Хил-эффект

Спрайт уже лежит в `Assets/Resources/Effects/HealCross.png` — назначать ничего не надо.

На объекте **Player** (в NewPlayScene) появились поля в инспекторе:
- **Heal Effect Duration** — сколько секунд живёт спрайт (ТВОЁ «X»)
- **Heal Effect Rise Speed** — скорость подъёма вверх (юнитов/сек, по умолчанию 1.5). ЭТО поле заменило старое Heal Effect Height
- **Heal Effect Sprite** — свой спрайт вместо креста (опционально)

Как теперь работает эффект:
- появляется ЗА игроком (крест рисуется ПОД спрайтом игрока, пока не уйдёт выше)
- поднимается строго вверх, без покачивания и без привязки к игроку
- растворяется с той же задержкой, что и раньше: первые 15% времени — появление, с 65% — растворение

Эффект срабатывает при лечении (`Player.Heal()`) — то есть при покупке у торговца.

## 3.1. Отладка: текущие HP и деньги в инспекторе

Не максимум, а именно текущие значения — можно менять прямо во время игры (Play Mode):

Эти поля — только для редактора (#if UNITY_EDITOR), в билд не попадают.

## 3.2. Кнопки: что было сломано и что исправлено

**Почему кнопки «умирали» в DeathScene (и не только):** переход сцен делает статический SceneTransition.SwitchToScene(), который обращается к объекту SceneTransition ТЕКУЩЕЙ сцены. В DeathScene такого объекта нет — ссылка указывала на уничтоженный объект прошлой сцены, каждый клик падал с NullReferenceException. Вне: нажатия ничего не давали.

Что исправлено (кодом, без правок сцен):
- **SceneTransition.SwitchToScene** теперь проверяет, жив ли объект: если в сцене SceneTransition нет (DeathScene, твоя будущая TutorialScene без префаба и т.п.) — переход делает сам: чёрное затемнение 0.2с → загрузка → открытие 0.3с. Настраивать ничего не нужно.
- Добавлена защита от повторных нажатий: пока переход идёт, повторные клики (в любую из кнопок) игнорируются — раньше двойной клик запускал две загрузки сцены одновременно.
- **ButtonCoolDown** (Attack/Dash кнопки): раньше если кнопка выключалась посреди кулдауна — она навсегда оставалась потухшей и некликабельной. Теперь при выключении состояние сбрасывается.
- **Имена триггеров аниматора** (нашлось при починке «В МЕНЮ» в обучении): в проекте ДВА префаба перехода с разными контроллерами — `SceneTransition.prefab` (триггеры sceneEnd/sceneStart) и `NewSceneTransition.prefab` (Close/Open). Старый код звал Close/Open вслепую — на SceneTransition.prefab переход зависал навсегда (в его клипе Ending к тому же нет события OnAnimationOver). Теперь скрипт читает фактические параметры аниматора и ставит таймер-страховку 2 сек: сцена активируется, даже если анимация не доиграла.
- **Разворот персонажа и УДАР**: раньше при отпущенном джойстике (вектор 0,0) и спрайт (`flipX = x < 0`), и оружие (`ActiveWeapon.FollowMousePos`) всегда отворачивались вправо — удар шёл не туда, куда персонаж смотрел. Теперь в `Player` есть единое свойство `FacingLeft`, которое обновляется только пока джойстик отклонён по X: спрайт (PlayerVisual.cs) и оружие вместе с хитбоксом (ActiveWeapon.cs) смотрят и бьют в последнюю сторону движения.

Обрати внимание (сам решай, надо ли чинить):
- На **AttackButton/DashButton** в NewPlayScene висит компонент со скриптом, которого нет в репозитории (в моей копии он выглядит как Missing Script — возможно, у тебя локально он есть). Если эти кнопки у тебя работают — ок, не трогай.
- **BuySwordButton / BuyBladeButton** в TradeScene: у них onClick вообще пустой в сцене — методы Buying.BuySword/BuyBlade нигде не подключены, поэтому они молчат всегда. Плюс сам Buying.cs не списывает деньги. Если хочешь — подключи методы в инспекторе, или скажи, я подключу кодом и доведу логику покупки.
- **ButtonCoolDown** держит кнопку некликабельной 1 секунду (Cool Down Time = 1) после нажатия — если кажется, что атака «не отвечает» при быстром спаме, уменьши это значение в инспекторе кнопки (у атаки реальный кулдаун 0.3с).

## 4. Система уровней и таймер

1. Открой `NewPlayScene`
2. Создай пустой объект `LevelSystem` → повесь скрипт **LevelSystem**
3. Настройки в инспекторе:
   - **XP Per Level Base** = 10 → уровень N требует N × 10 XP (2-й уровень: 10 XP, 3-й: 20 суммарно и т.д.)
   - **Sword Bonus Per Level** = 1 → меч: +1 урона за уровень

Как это работает:
- У каждого `EnemySO` (SceletonSO и т.д. в `Assets/ScriptableObjects`) появилось поле **XP Reward** (по умолчанию 5). XP даётся при убийстве.
- У **Sword** (в инспекторе оружия) появились `Base Damage` и `Scale With Level`.
- Уровень живёт один забег: при загрузке NewPlayScene сбрасывается.
- При смерти сохраняются: `last_run_time`, `last_run_level` + рекорды `best_time`, `best_level`.

## 10. Сборка дебаг-версии под Android (чеклист)

В проекте для Android уже стоит Scripting Backend **IL2CPP** (Project Settings → Player → Android → Configuration → Scripting Backend). Это правильный вариант «как в релизе», но медленный: первая сборка легко занимает 15–30 минут — IL2CPP конвертирует C# в C++ и компилирует его NDK, а Gradle при первом запуске ещё и качает зависимости. «Висит 15–20 минут» — чаще всего НЕ зависание, а нормальная первая сборка. Повторные собираются заметно быстрее (кэш IL2CPP и Gradle).

### Один раз — среда
- [ ] Unity Hub → Installs → 6000.3.9f1 → модули: **Android Build Support**, внутри него **OpenJDK** и **Android SDK & NDK Tools**. Если чего-то нет — Add Modules, дождаться загрузки
- [ ] Телефон: Настройки → О телефоне → 7 тапов по «Номеру сборки» → в появившемся меню «Для разработчиков» включить **Отладку по USB**
- [ ] На диске C: свободно 10+ ГБ (Gradle-кэш и IL2CPP любят место)

### Перед сборкой
- [ ] **File → Build Profiles → Android → Switch Platform.** После пересоздания Library платформа слетает на Windows — свитч обязателен. Первый свитч переимпортирует ВСЕ ассеты под Android (текстуры → ETC2/ASTC) — до получаса «тишины», это норма
- [ ] В том же окне проверь **Scene List**: должны быть MainMenu, NewPlayScene, DeathScene и **TutorialScene**. В копии репозитория TutorialScene в списке НЕТ (она создаётся локально по SETUP.md) — открой сцену и нажми Add Open Scene
- [ ] Project Settings → Player → вкладка **Android**:
  - Other Settings → Identification → **Package Name**: для Android он сейчас не задан — впиши `com.KyrbanovProd.Witch` (или свой)
  - Other Settings → Configuration → **Target Architectures**: ✅ ARMv7 + ✅ ARM64 (ARM64 обязателен для Google Play)
  - Resolution and Presentation → **✅ Optimized Frame Pacing** (для наших 60 FPS, см. раздел 9)
- [ ] Сохрани сцены (Ctrl+S), убедись, что не в Play Mode

### Сама сборка (дебаг)
- [ ] File → Build Profiles → Android → галка **✅ Development Build** — это и есть «дебаг»
- [ ] Debug Settings: **Wait for Managed Debugger — ВЫКЛ** (иначе игра зависнет на старте в ожидании отладчика); Script Debugging тоже не нужен, если не подключаешься отладчиком
- [ ] Расширение: **APK** (не AAB — AAB на телефон напрямую не ставится)
- [ ] Подпись не нужна: debug-сборка подписывается автоматическим debug-keystore
- [ ] Подключи телефон, на его экране нажми «Разрешить» (отпечаток RSA) → жми **Build And Run**: соберёт, установит и запустит
- [ ] Альтернатива: Build → скинуть APK на телефон → установить (разреши «установку из неизвестных источников»)

### Если «собирается и ничего» — как понять, на каком этапе
1. Правый верхний угол редактора: крутится маленький индикатор — работа идёт (переимпорт / компиляция / Gradle)
2. **Editor.log — главный источник правды**: Windows → вставь в адресную строку Проводника `%LOCALAPPDATA%\Unity\Editor\Editor.log` и смотри последние строки: Reimporting assets → IL2CPP → Gradle → Packaging. Какой этап — такой и «висит»
3. Console: есть ли красные ошибки. На ошибках компиляции сборка падает сразу и громко, а не молчит
4. Телефон виден? `adb devices` (adb: `C:\Program Files\Unity\Hub\Editor\6000.3.9f1\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\adb.exe`)
5. Всё-таки застряло: закрой Unity → Диспетчер задач → убей java.exe и gradle-процессы → удали папку `Temp` в корне проекта → собери заново
6. Антивирус может проверять каждый файл Gradle/Temp — добавь папку проекта и папку Unity в исключения

### Известная ошибка: Could not find or load main class com.google.prefab.cli.AppKt

Появляется на этапе Gradle (упаковка APK: `installDebug` → `configureCMakeDebug[arm64-v8a]`), когда компиляция самой игры уже прошла успешно. Причина — **имя пользователя Windows написано кириллицей**: Gradle кладёт кэши в `C:\Users\<имя>\.gradle\caches`, и когда сборка запускает java с путём к инструменту Prefab из этой папки, кириллические символы затираются в `?` — Java не находит jar. В логе это видно буквально: путь вида `C:\Users\???\...` (и короткое имя `C:\Users\5C0C~1\...` для Temp — тот же признак).

Лечение — перенести кэши Gradle на путь без кириллицы:
1. Win+R → `sysdm.cpl` → вкладка «Дополнительно» → «Переменные среды»
2. В блоке «Системные переменные» → «Создать»: имя `GRADLE_USER_HOME`, значение `D:\gradle-home` (только латиница и без пробелов; папку создавать не нужно — Gradle сделает сам)
3. ПОЛНОСТЬЮ закрой Unity, в Диспетчере задач убей оставшиеся `java.exe` (это старые демоны Gradle), надёжнее всего — перезагрузить ПК
4. Собери заново: первый раз зависимости скачаются в новую папку (плюс несколько минут), дальше — из кэша. Проверка, что сработало: в новом логе пути кэшей должны быть `D:\gradle-home\...`, а не `C:\Users\...`

Если не помогло, по нарастающей:
- удали папку `<проект>\Library\PramData` и собери заново
- План B: Параметры → Время и язык → Язык и регион → Административные языковые параметры → «Изменить язык системы…» → ✅ «Beta: Использовать Юникод (UTF-8)» → перезагрузка (у старых программ может поехать кодировка — галочка выключается обратно)
- План C: новый пользователь Windows с именем латиницей (радикально, но лечит все подобные проблемы разом)
